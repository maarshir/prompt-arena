# promptdiff

[![Тесты](https://github.com/maarshir/promptdiff-/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/maarshir/promptdiff-/actions/workflows/tests.yml)

Сравнивает варианты промпта на одном наборе задач и показывает, на каких задачах они ответили по-разному. Для тех, кто правит промпты и хочет видеть, что починил и что сломал.

```
$ python run.py --prompts prompts/support_ticket.yaml --cases cases/support_ticket.yaml

вариант       прошло   нет  сбой   токены вх/вых     сек        цена
short          4/7       3     0         1260/84     5.6    $0.00504
rules          7/7       0     0         2310/84     5.6    $0.00819

Цена ответов: $0.01323, потрачено в этом запуске: $0.01323 (цены claude-sonnet-4-6 на 2026-09-27, token-counter)

Расхождения (задача: кто прошёл):
  phone_from_8: short нет, rules да
  urgent_negated: short нет, rules да
  two_numbers: short нет, rules да
```

Это настоящий вывод программы, но ответы модели в нём написаны вручную (модель подменена, как в тестах): настоящего прогона в репозитории пока нет.

Главное здесь нижний блок. Средний балл может вырасти, пока половина задач ломается, а список расхождений сразу показывает, где именно один вариант справился, а другой нет. Сбои сети выводятся отдельно и в расхождения не попадают.

## Установка

```bash
git clone https://github.com/maarshir/promptdiff- promptdiff && cd promptdiff
pip install -r requirements.txt
cp .env.example .env    # и вписать ключ Groq или Anthropic
```

Нужен Python 3.10+. Адрес репозитория кончается дефисом, поэтому папка в команде названа явно.

## Использование

```bash
# что уйдёт в модель и прикидка цены сверху, без ключа и без запросов
python run.py --prompts prompts/support_ticket.yaml --cases cases/support_ticket.yaml --dry-run

# прогон
python run.py --prompts prompts/support_ticket.yaml --cases cases/support_ticket.yaml
python run.py --prompts prompts/ticket_topic.yaml --cases cases/ticket_topic.yaml
```

В репозитории два набора: разбор обращения клиента в поля (номер заказа, телефон, срочность) и тема обращения одним словом. Свои наборы кладутся рядом.

**Бесплатно через Groq.** Возьмите ключ на [console.groq.com/keys](https://console.groq.com/keys) и впишите в `GROQ_API_KEY`. Если задан только он, прогон сам идёт через Groq на `openai/gpt-oss-120b`, не чаще 20 запросов в минуту (меняется `--rpm`); при ответе 429 клиент ждёт столько, сколько сказал сервер. Набор из 14 запросов идёт около минуты. Лимиты бесплатного уровня смотрите на [странице Groq](https://console.groq.com/docs/rate-limits).

**Через Anthropic.** Впишите `ANTHROPIC_API_KEY`, модель по умолчанию `claude-sonnet-4-6`.

Параметры: `--model`, `--provider groq|anthropic`, `--rpm`, `--limit` (одновременных запросов, по умолчанию 5), `--out` (JSON с ответами, по умолчанию `results/`), `--no-cache`, `--cache-dir`, `--prices`.

Ответы кэшируются на диске: тот же запрос второй раз в модель не уходит, платите только за новое. Цена каждого варианта считается через [token-counter](https://github.com/maarshir/token-counter), отдельно цена ответов и сколько потрачено в этом запуске.

## Как описать задачи и варианты

Задачи, `cases/support_ticket.yaml`:

```yaml
- id: urgent_negated
  input: Не срочно, но подскажите, где сейчас заказ 1204
  expect:
    contains_all: ["urgent=no", "order=1204"]
  note: слово «срочно» есть, но с отрицанием, частая ошибка
```

Варианты, `prompts/support_ticket.yaml`: список из `id`, `note` и `prompt` (уходит в модель как системный промпт, `input` задачи как сообщение пользователя).

Проверки: `exact` (точный ответ), `contains_all` (все нужные куски на месте), `contains_none` (нет лишнего вроде «Вот ответ:»). Каждая даёт да или нет, баллов нет специально. Регистр, пробелы и точка в конце не мешают, а число не режется посередине: `order=12` не находится в `order=1204`. Загрузчик падает с понятной ошибкой на опечатке в названии проверки или на `yes` без кавычек.

Проверки без модели на ответах, написанных руками: `python -m examples.check_by_hand`.

## Что было непросто

- **Сбой сети не должен выглядеть как плохой промпт.** Если один вариант получил 529, а другой нет, простое «прошло или нет» покажет ложное расхождение. Поэтому сбой хранится отдельно и в расхождения не попадает.
- **Граница числа.** Поиск подстроки засчитывал `weight=0.35` за `weight=0.3`. Граница слова не годится для русского: «заказ» перестал бы находиться в «заказу». Граница ставится только у цифр.
- **Ключ кэша.** Он должен меняться от всего, что меняет ответ (поставщик, модель, промпт, вход, потолок длины), иначе после правки промпта прогон тихо отдаст старые ответы.
- **Бесплатный уровень и 429.** Ограничитель заранее разводит запросы по времени, а при отказе пауза берётся из `retry-after`, а не наугад.
- **Два поставщика с разными форматами.** Всё, что различается у Anthropic и Groq, собрано в `core/providers.py`; повторы, кэш и цена общие.

Подробнее о каждом решении и о выборе технологий: [docs/решения.md](docs/решения.md).
